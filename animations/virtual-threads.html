Why virtual threads scale blocking code

Every task does 1 tick of CPU, waits on I/O (a database call, an HTTP request), then does 1 more tick of CPU. A platform thread sits idle during the wait. A virtual thread unmounts from its carrier, so the carrier runs someone else. Unless it is pinned: in Java 21, blocking inside synchronized keeps the carrier busy.
